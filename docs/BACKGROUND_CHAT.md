# 答疑后台生成与重连

带 `request_id` 的 `/api/chat/stream` 请求由后端独立任务消费完整的原有答疑流。页面关闭、刷新或客户端 SSE 断开只解除订阅；输出过滤、计费、积分和数据库保存仍由原答疑链路执行。任务持有独立数据库 Session 和题图副本，不依赖已结束的 HTTP 请求资源。

前端在发送前将请求标识、会话、学科、问题及已有消息数按用户写入 localStorage。重新进入学生答疑页时，用 `GET /api/chat/stream/{request_id}` 重放已有事件并继续订阅；恢复不会重新提交问题或再次上传图片。同一个用户重试同一个请求标识只接入原任务，载荷不一致返回 409。主动停止使用 `DELETE /api/chat/requests/{request_id}`，取消生成并沿用原有部分内容保存和资源释放逻辑。

运行边界：

- 依赖当前部署的单个 uvicorn worker。扩容到多个 worker 前必须将任务路由和事件存储迁移到共享服务。
- 退出客户端可后台继续；后端服务重启或机器断电不能继续尚未完成的模型计算。已完成内容仍在学习记录中，完成请求也可通过原有 Redis 重放记录恢复。
- 内存事件保留 30 分钟，最多 1000 个请求（满时回收已完成记录），每个用户最多 3 个活跃任务，单任务最多 15 分钟。已保存的学习记录不随事件缓存过期而删除。
- 浏览器禁止或清除 localStorage 时，不能自动定位上次请求；仍可从学习记录查看已保存内容。
- `sse_active_connections` 继续表示实际 SSE 订阅连接数，不包含无人订阅的后台生成任务。

验证：`tests/test_background_chat.py` 覆盖思考中断连、请求 Session 关闭后完整保存、重连单次模型调用、用户隔离、载荷冲突、显式取消/关闭清理以及内存过期后的完成重放。`frontend/tests/chatStreamReliability.test.ts` 覆盖恢复使用 GET 且不重新提交问题。
