# 旧 Android 平板系统导航栏覆盖操作区

用户照片显示，未弹出输入法时，Android 底部三键栏覆盖了添加题图、深度推理及发送按钮。
上一轮 899421d 的视口缩小与换行修复不能证明避让了系统栏；16px 底部留白也不足以兜底。
照片无法识别设备实际加载的前端版本，不能仅凭照片确定它是在 899421d 发布前还是发布后拍摄。

## 修复

- 在既有视口同步入口识别 Android，为聊天操作区预留额外 72 CSS px。
- 旧 WebView 即便 safe-area 为 0、视口未扣除导航栏，按钮仍保持上移；系统报告更大安全区时取更大值。
- CSS 使用 calc() 普通声明在前、max()/env() 增强声明在后，避免旧引擎忽略整条底部留白。
- 同时给聊天侧栏退出按钮留出空间，包括 compact 规则。非 Android 不添加 72px 预留。
- 属于保守网页兜底：已正确扣除系统栏的新 Android 壳也会额外留白，以换取旧设备可操作性。
  本次网页修复无需预先安装新 APK；原生 IME 修复与真实键盘验收仍独立。

## 验证

- ego-browser 使用 Android 8.1 / Chrome 74 UA（实际渲染引擎仍是本机 Chromium），
  注入覆盖页面底部 72px 的系统栏，模拟 WebView 未缩小视口且 safe-area 为 0。
- 1280×800、1024×768、1024×340、768×280、375×300、320×280，
  各测试展开/折叠侧栏、发送/停止，共 24 种组合；题图按钮、推理标签及发送/停止按钮
  在全部组合中完整位于模拟系统栏上方，中心点击命中正常。
- 首轮模拟额外发现 compact 侧栏 padding-block 覆盖预留，已将其改为显式 padding-top/padding-bottom；
  这项后续 CSS 修正未重新做浏览器模拟，不能将首轮侧栏检查报告为全部通过。
- Node 前端 16 个测试文件通过，包含 Android 识别及切换回非 Android 的行为；平板布局 pytest 9 项通过。
- 截图及原始 24 组数据：artifacts/android-navigation-20261027/。
- 无真实平板连接；UA 模拟不能证明实际 Chrome 74、厂商导航栏和输入法均已验收。
